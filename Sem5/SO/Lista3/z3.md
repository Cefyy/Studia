#### arch_do_signal_or_restart

Jeśli mamy jakiś sygnał który ma customowy handler to nasze get_signal zwróci true i jądro musi przejąć kontrole i przygotować program do jego obsługi
to bedzie się działo w:

#### -> handle_signal

 ```C
    sigset_t *oldset = sigmask_to_save();
 ```

 zapisujemy starą maskę sygnałów i w zależnosci czy proces jest x32 czy x64 odpalamy odpowiednią funkcje tworzącą ramke sygnału.
 Skupmy się na:

#### -> setup_rt_frame

Tworzymy ramkę sygnału która trzyma informację o nim i kontekscie procesora, zapisywana jest w całości na stosie procesu.

```C

 frame = get_sigframe(ksig, regs, frame_size);
 if (!access_ok(frame, frame_size))
 return -EFAULT;

```

tutaj jeśli stos nie jest przepełniony ani uszkodzony alokujemy ją w pamięci procesu

```C
 err |= copy_siginfo_to_user(&frame->info, &ksig->info);

/* Create the ucontext. */
err |= __put_user(0, &frame->uc.uc_flags);
err |= __put_user(NULL, &frame->uc.uc_link);
err |= __save_altstack(&frame->uc.uc_stack, regs->sp);
err |= setup_sigcontext(frame, regs);
err |= __copy_to_user(&frame->uc.uc_sigmask, set, sizeof(*set));
```

zapisujemy informację o sygnale i bardzo ważna funkcja:

```C
err |= setup_sigcontext(frame, regs);
```

która kopiuje wszystkie wartosci rejestrów ze stosu jądra do pamięci użytkownika
po za tym zapisywana jest tez maska sygnałów

```C
#ifdef CONFIG_MMU
 regs->ra = (unsigned long)VDSO_SYMBOL(
  current->mm->context.vdso, rt_sigreturn);
```

W Risc-V mamy jednostke zarządzania pamięcią MMU, tutaj uzywając rejestru ra i kodu vDSO zapisujemy sygnał powrotu, kiedy signal handler wywoła ret to procesor skoczy pod adres gdzie wskazuje ra, czyli pod rt_sigreturn

```C
regs->epc = (unsigned long)ksig->ka.sa.sa_handler;
regs->sp = (unsigned long)frame;
regs->a0 = ksig->sig;                     /* a0: signal number */
regs->a1 = (unsigned long)(&frame->info); /* a1: siginfo pointer */
regs->a2 = (unsigned long)(&frame->uc);   /* a2: ucontext pointer */
```

Tutaj modyfikujemy wartosci rejestrów, zostaną one załadowane do fizycznych reejestrów procesora, gdy jądra odda władze nad procesem użytkownikowi
nadpisujemy licznik instrukcji, tak zeby zamiast wrócić do miejsca przerwania wróci do handlera
stack pointer teraz bedzie wskazywał na signal frame

a0,a1,a2 zgodnie z Calling Convention architektury RISC-V trzyma pierwsze trzy argumenty wywołania funkcji
