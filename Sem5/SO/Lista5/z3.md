Nie można modyfikować katalogów za pomocą read i write, ponieważ katalogi to nie listy tekstowe ale często skomplikowane struktury danych jak np. B-Drzewa czy tablice haszujące. Zwykły program mógłby uszkodzić strukturę systemu plików nadpisując jakies wrazliwe dane, a zablokowanie read ułatwia pracę ponieważ trzeba by było znać binarny format każdego systemu plików. Tą pracę robi jądro które parsuje te struktury i pokazuje dane w czytelnym interfejsie. Próba uzycia tych wywołań zwraca błąd EISDIR(is a directory)

By wczytać rekord katalogu,czyli pojedynczy wpis katalogu należy skorzystać z wywołania systemtowego getdents ( od get directory entry),
funkcja C readdir jest jedynie nakładką na to wywołanie systemowe.

Dane nie są posortowane, głównie ze względu na wydajność, gdyby za każdym razem gdy system plików tworzy nowy wpis musiał za każdym razem sortować wszystkie pliki to byłoby to wysoce nieefektywne. Zamiast tego po prostu wstawia nowe wpisy w pierwsze wolne miejsca - na koniec katalogu lub w lukę powstałą po usunięciu innego wpisu. Jądra zwraca wpisy w kolejnosci takiej jakiej są ustawione w strukturze, a za alfabetyczne wyswietlenie odpowiada dopiero aplikacja koncowa np. ls

By wyświetlić metadane katalogu, czyli informacje o samym katalogu, a nie o jego zawartosci należy uzyc komendy
```bash
stat /
```
