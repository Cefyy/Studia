ps -eo user,pid,ppid,pgid,tid,pri,stat,wchan,cmd

-e - select all processes
-o wybór formatu

user - effective user name
pid - numer reprezentujący id procesu
ppid - id procesu rodzica
pgid - process group id
tid - id jednostki wykonującej (wątku???????)
pri - priorytet czym wyzszy numer tym wiekszy priorytet (duh)
stat - process state code
wchan - nazwa funkcji jądra w której proces oczekuje jakies waity,
sleepy albo często puste
cmd - komenda jaka wywołała ten proces

init - który ma pid 1 ma ppid 0 czyli nie ma żadnego procesu
rodzica ponieważ uruchamia go sam kernel

rodzic - dziecko - oznacza że większość procesów ma rodzica
który go wywołuje na to wskazuje właśnie ppid

STAT -
D uninterruptible sleep (usually I/O)
I idle kernel thread
R running or runnable (on run queue)
S interruptible sleep (waiting for an
event to complete)
T stopped by job control signal
t stopped by debugger during the tracing
W paging (not valid since Linux 2.6)
X dead (should never be seen)
Z defunct (“zombie”) process, terminated
but not reaped by its parent  
Za wątki odpowiada kthreadd czyli beda miały ppid 2 (lub sam kthreadd) i
w comm czyli nazwie bedzie []

ps --pid 2 -p 2 -f - by wyswietlic wszystkie

wątki odpowiadają za wykonywanie się procesu, mają zestaw rejestrów, licznik programu i stack

Hierarchia procesów to pojęcie opisujące wykorzysatnie relacji rodzic dziecko, jak juz wspomniałem
wiekszosc procesów ma swojego rodzica który go wywołał, jednego a procesy moga miec 0,1 wiecej dzieci
Tak tworzą grupy procesów, zaczynając od procesu init.

pstree - wywołuje drzewo procesów, wątki to w {}
